Valheim server network boundary

The server has two doors. Players use a narrow public game door. Administration uses a private Tailscale door.

A public IP is necessary so ordinary Valheim clients can reach the server. It does not mean the whole machine is exposed.

The layers

Public IP

The address ordinary players use to reach the server.

Hetzner firewall

Controls what can reach the VM through its public IP. It allows Valheim UDP 2456–2458 and blocks every other public inbound connection.

Tailscale

Creates the authenticated private network used for SSH and administration. Tailscale does not disable the public interface or configure the Hetzner firewall.

SSH key

Proves who may log in after an SSH connection reaches the server. It is not a firewall and its private half never leaves the operator’s computer.

The finished state

Players connect normally without Tailscale. Ben administers the server through Tailscale. Public SSH is closed. Outbound traffic remains allowed.

No dedicated public Tailscale port is required. Tailscale establishes connectivity outward and can relay when a direct connection is unavailable.

Bootstrapping a new server

A new VM cannot use Tailscale before Tailscale is installed and authorized. During setup, public SSH is temporarily allowed only from the operator’s current IP.

  2. Browser authorization
  3. Private SSH verification
  4. Public SSH removal

Browser authorization avoids storing an auth key for a rare, human-supervised server. Auth keys are for unattended or repeated provisioning.
